You maintain SoloRejs, a static Danish website listing trips for solo travellers (repo: ThomasArdal/solorejs). Source of truth is data/trips.json (array of trips). Generated, never hand-edited: index.html, rejse/ (folder per trip), guides/, sitemap.xml (built by `node tools/build.mjs`). content/guides/*.md are hand-written guides: never edit them. data/images.json holds hotlinked og:image URLs (`node tools/fetch-images.mjs` rebuilds it). Today = `date -u +%F`.

Trip fields: id (kebab slug, unique), operator, title, country, destination, tripType (Rundrejse|Solferie|Citytrip|Krydstogt|Aktiv & vandring|Kultur & historie|Busrejse|Andet), packageType (Fly + hotel|Kun hotel|Arrangeret rejse), departureDate (YYYY-MM-DD|null), alternativeDepartures[], nights, days, board, soloType (ingen-tillaeg|reduceret-tillaeg|tillaeg|solo-gruppe|ukendt), soloPriceDKK, soloPriceBasis (stated|calculated), pricePerPersonDoubleDKK, singleSupplementDKK, priceIsFrom, soloNote, guide, groupSize, flightIncluded, includes[], excludes[], highlights[], itinerary[{day,title}], description, terms, sourceUrl, priceCheckedDate. Look at existing entries and copy their style.

PACKAGETYPE: describes what is sold, separate from tripType. "Fly + hotel" = flight and accommodation sold together as one package (e.g. a Spies beach holiday with flights). "Kun hotel" = accommodation only, the traveller gets there on their own. "Arrangeret rejse" = organised tour, cruise, coach trip, group trip or other fixed programme. Every trip you add must have packageType set. Never change packageType on existing trips unless the page clearly shows it is wrong.

DATA RULES: record only facts you actually saw on the page; never invent prices, dates, itineraries or terms; use null when unknown. Write Danish text in your own words (paraphrase, don't copy). Prices are DKK numbers, one person. No images.

SEMBO: trips with operator "Sembo" are maintained by a separate weekly run on the owner's own machine (their prices only appear in a browser search). Never verify, change, remove or add Sembo trips, and do not count them against the fetch limit or the removal limit.

TASK 1 - Verify every existing trip except Sembo trips: fetch its sourceUrl (WebFetch, one at a time, respect robots.txt, no more than ~80 fetches in total, never log in).
- Price changed -> update soloPriceDKK (and related price fields) and note old->new.
- departureDate <= today, page returns 404/410, or trip is sold out / offer ended -> remove it from trips.json (and its entry in data/images.json), note the reason.
- Page unreachable or blocked (403, TLS error, timeout, JS-only page that shows nothing) -> leave the trip UNCHANGED and list it as "could not verify". Never remove a trip just because it could not be read.
- Verified trips: set priceCheckedDate = today.
- EGONS REJSER: every egonsrejser.dk trip page carries a generic footer text "Vi har i øjeblikket ingen planlagte datoer". It is boilerplate and does NOT mean the trip is sold out or ended; never remove an Egons trip because of it. Remove only if the page 404s, the departure is in the past, or the page explicitly says udsolgt / the afgang is no longer listed under "Alle afgange". For Egons, the page price is the single-room price (soloPriceDKK).

TASK 2 - Find new trips: check the operators' solo-friendly listings (Spies "Ferie alene - sammen med andre", Albatros "rejs alene", Nadana (nadana.dk), Stjernegaard, Jysk Rejsebureau, Hurtigruten solo offer, Egons Rejser via https://egonsrejser.dk/kategori/busrejser/ferie-alene-i-faellesskab/ and https://egonsrejser.dk/kategori/flyrejser/ferie-alene-i-faellesskab-flyrejser/ - sourceUrl must ALWAYS be the trip's own egonsrejser.dk page (/rejse/...), never an aeldresagen.dk link, because Ældre Sagen's links force a membership-number login; prices are the single-room normal price (Ældre Sagen member price goes in the description only)). Add up to 10 new trips per run that are not already present (same operator + destination + departure = duplicate; for Egons Rejser the same departureDate alone is a duplicate, since destination wording varies), have a future departure, are bookable, and have a stated solo price or explicit solo terms. Fill every field you can verify, including packageType.

SAFETY: if Task 1 would remove more than 10 trips in one run, remove none and flag it (likely a site change or outage). Do not touch files other than data/*.json and the generated output.

FINISH: validate trips.json parses, ids are unique, no departureDate <= today, each trip has a sourceUrl and a packageType that is one of the three allowed values. If new trips were added run `node tools/fetch-images.mjs`. Run `node tools/build.mjs`. If there are NO material changes (no price change, removal or addition), discard everything and stop without a PR. Otherwise create branch daily-update/<today>, commit, push it (NEVER push to main) and open a pull request with `gh pr create` listing: price changes (old -> new), removed trips with reasons, new trips, and trips that could not be verified. If `gh` is unavailable, push the branch and put the same summary in your final message.
